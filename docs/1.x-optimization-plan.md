# HaloCap 1.x 优化计划：OCR 与录屏

> 状态：v1.4.0 已发布（M1 OCR 完成）；M2 录屏待开始  
> 更新时间：2026-10-30  
> 适用范围：HaloCap 1.x，Windows 10+（当前最低 1903）  
> 不在本文范围：2.0 原生重构、Windows 7/8、macOS

## 1. 目标与边界

### 1.1 版本边界

- **1.x 只支持 Windows 10+**，继续使用 WPF，不进行原生重写。
- Windows 7/8、macOS 的低内存原生版本放在 **2.0**，本文不展开实现。
- 1.x 的定位是**功能补齐和体验优化**，不为了跨平台牺牲 Windows 体验。

### 1.2 优化目标

- OCR：原生 / 模型双引擎，按行输出，支持搜索、逐行复制、贴图入口。
- 录屏：支持麦克风与系统音频，可选分辨率、帧率、画质，支持窗口/区域录制、60fps、倒计时与暂停/恢复。
- 交互原则：键盘优先、一步进入、即时反馈、少打断，保持 Snipaste 式的操作节奏。
- 所有设置持久化，首次使用有合理默认值，不引入 FFmpeg 或重型依赖。

### 1.3 内存目标与 1.x 边界

- 1.x 的正式验收目标：**不因新功能造成内存明显回退**；4K 录制尽量控制在 500MB 以内。
- WPF/.NET 自身基线约 185MB，**1.x 无法达到空闲 <100MB**；严格的空闲 <100MB、4K 录制 <500MB 作为 2.0 原生版的正式目标。
- 录制参数（分辨率/帧率/画质）本身也是内存控制手段：遇到高负载时，界面应引导用户选择更低分辨率或帧率。

## 2. 现状与差距

### 2.1 OCR（v1.4.0 前的基线）

现有实现：

- [`OcrService.cs`](../src/HaloCap/Services/OcrService.cs) 每次识别重新创建引擎。
- 图像走 `BitmapSource → byte[] → PNG → SoftwareBitmap` 的往返，4K 图像下延迟和内存偏高。
- 只使用 `OcrResult.Lines`，没有利用词框恢复段落、列和阅读顺序。
- 语言策略是中文优先、英文其次、最后系统语言，没有用户可选的多语言组合。
- [`OcrResultWindow.xaml.cs`](../src/HaloCap/UI/OcrResultWindow.xaml.cs) 以逐行按钮和复制全部为主，不能选中文本、搜索或保留排版。
- 没有从贴图发起的 OCR 入口。

### 2.2 录屏

现有实现：

- [`RecordingSession.cs`](../src/HaloCap/Services/RecordingSession.cs) 固定 30fps，WGC 抓帧后复制到 CPU 字节数组，再由 Media Foundation 编码。
- 只录制画面，不包含麦克风或系统音频。
- 只支持单显示器区域录制，不支持窗口录制。
- 没有分辨率、帧率、画质、光标采集等可选参数。
- 没有倒计时、暂停/恢复；[`RecordingHudWindow.xaml.cs`](../src/HaloCap/UI/RecordingHudWindow.xaml.cs) 目前只有停止操作。

### 2.3 基线数据

- 托管堆约 2.3MB；一次选区后 GPU 进程内存约 330MB，WPF 私有内存约 400–500MB。
- 当前空闲私有内存约 185MB。
- 自动化回归测试 58/58 通过。
- 这些数据作为 1.x 优化的对照基线，不把“GC 回收”当作内存优化的主要手段。

## 3. OCR 优化（v1.4.0 已实现）

### 3.1 设置项

| 设置 | 选项 | 默认值 |
| --- | --- | --- |
| 识别引擎 | 原生 / 模型 | 原生 |
| 自动复制 | 开 / 关 | 关 |
| 贴图 OCR | 开 / 关 | 开 |

不提供主语言 / 辅助语言选择，也不重建排版；两种引擎都按检测到的文本行输出。

### 3.2 原生引擎

- 使用 `Windows.Media.Ocr`，自动优先中文，其次英文，再使用系统可用语言。
- 缓存 `OcrEngine`，避免每次重新创建。
- 直接从 BGRA 像素创建 `SoftwareBitmap`，移除 PNG 编解码往返。
- 识别放到后台线程执行；仅按引擎最大尺寸限制做下采样，不做放大或灰度预处理。
- 缺少中文语言组件时保留安装引导；不会弹出语言选择。

### 3.3 模型引擎

- 内置 PP-OCRv6 tiny 轻量模型：检测约 1.8 MB、识别约 4.5 MB，配 PP-OCRv5 文本方向分类模型和字典，合计约 7 MB；Apache-2.0。
- 使用 ONNX Runtime + RapidOcrNet 在本机完成 DBNet 检测与 CRNN 识别，不依赖 Windows 语言包，不访问网络。
- 模型作为程序集资源嵌入，首次使用时解压到 `%LOCALAPPDATA%\HaloCap\models`。
- 识别在后台线程执行，按检测框从上到下、从左到右输出文本行；不做主辅语言合并、不重建段落或缩进。
- 模型不可用或初始化失败时明确提示，可在结果窗口一键切回原生引擎。

### 3.4 结果体验

- 结果为可选中文本，按行输出；支持 `Ctrl+F` 搜索、文本 / 逐行视图切换、逐行复制、复制全部和原图缩略图。
- 结果窗口顶部可在原生 / 模型间切换，直接重新识别当前图片，不需要重新框选。
- 设置中可开启自动复制。
- 截图工具栏、文字识别快捷键、贴图右键 / `O`共用同一个结果窗口。
- 贴图 OCR 使用贴图原图，不包含后加标注。

### 3.5 验收标准

- 原生与模型引擎分别覆盖中文、英文、中英混排、代码、UI、深色背景和小字样本。
- 模型首次使用时能解压并初始化，断网环境下可用；原生缺少语言包时给出安装引导。
- 结果按行输出，搜索、逐行复制、原图缩略图、引擎切换和自动复制正常。
- 自动化回归测试 66/66 通过；截图 / 标注 / 贴图流程不回归。

## 4. 录屏优化（建议 v1.5 视频与控制，v1.6 音频与可靠性）

### 4.1 可选参数与默认值

| 设置 | 选项 | 默认值 |
| --- | --- | --- |
| 输出分辨率 | 原始大小 / 2160p / 1440p / 1080p / 720p | 原始大小 |
| 帧率 | 30 / 60 fps | 30 |
| 画质 | 高 / 均衡 / 紧凑（自动码率） | 均衡 |
| 系统声音 | 开 / 关 | 开 |
| 麦克风 | 开 / 关 | 关 |
| 音频码率 | 128 / 192 kbps | 192 |
| 光标 | 录制 / 不录制 | 录制 |
| 倒计时 | 关闭 / 3 秒 / 5 秒 | 3 秒 |
| 录制范围 | 区域 / 窗口 | 区域 |

- 分辨率只做下采样，不放大；保持宽高比，输出为偶数尺寸。
- 若选择的分辨率高于选区/窗口原始尺寸，自动限制到原始尺寸。
- 60fps 和 4K60 依赖硬件编码能力；界面显示预计负载，不稳定时提示回退 30fps 或 1440p。
- 画质档位自动计算码率，也可预留自定义码率入口。

### 4.2 录制范围

- **区域**：沿用现有选区体验，支持移动/调整。
- **窗口**：使用 WGC 窗口捕获；窗口移动/缩放时按窗口当前尺寸输出；窗口关闭或最小化时停止并保存。
- 窗口录制需要处理 WGC 的系统边框提示（可用时关闭或弱化，按系统版本判断）。
- 区域/窗口切换不改变现有快捷键与倒计时流程。

### 4.3 控制与 HUD

- 选区完成后倒计时，再开始录制。
- HUD 显示：录制时长、文件大小、麦克风电平、暂停/继续、停止。
- HUD 与录制边框不进入视频（继续使用 `WDA_EXCLUDEFROMCAPTURE`）。
- 暂停/恢复同时作用于视频和音频；恢复后时间轴连续。
- 支持暂停/停止快捷键；状态与托盘菜单同步。
- 录制完成后可打开文件/所在目录。

### 4.4 性能与编码

- WGC 纹理直接交给硬件 H.264 编码器，避免 CPU 全帧拷贝。
- 保留软件编码回退；硬件不支持 60fps/4K60 时自动降级并提示。
- 有界帧队列、帧率节奏、静态画面重复帧，避免长时间无变化时文件时长为 0。
- 音频使用独立队列和时间戳；音画同步目标漂移 < 50ms。
- 4K30 作为 1.x 稳定目标；4K60 标记为“硬件相关”；1080p60/1440p60 作为常规验收档位。

### 4.5 音频

- WASAPI 系统回环 + 麦克风采集，48kHz 立体声。
- 混音后使用 AAC 编码；支持独立开关、音量、静音。
- 默认设备变化/设备拔出时暂停并提示，避免无声录制。
- 无音频设备时允许静默录制，HUD 给出提示。
- 暂停/恢复时音频时间戳与视频一致。

### 4.6 可靠性

- 录制前检查磁盘空间；磁盘不足时拒绝开始或提示更换目录。
- 异常/窗口关闭/设备丢失时尽量保留可播放文件。
- 文件命名、保存目录沿用现有设置。
- 长时间录制（10–30 分钟）不丢音、不漂移、不异常退出。
- 录制结束后做一次内存回收并记录内存/丢帧指标。

### 4.7 验收标准

- 1080p60、1440p60 稳定；4K30 稳定；4K60 视硬件。
- 区域、窗口、暂停/恢复、倒计时、音频开关、设备切换均可用。
- 音画同步 < 50ms；30 分钟录制可正常播放。
- 4K 录制尽量 < 500MB；无法满足时给出降低分辨率/帧率的建议。
- 录制期间记录 CPU/GPU/内存/丢帧，作为后续 2.0 基线。

## 5. 1.x 内存与兼容收尾（建议 v1.7）

- 继续释放冻结画面、放大镜、标注和剪贴板缓存；录制结束触发回收。
- 1.x 空闲内存目标为“不明显回退”；当前的 WPF 基线无法达到 <100MB，正式目标放到 2.0。
- 评估 Windows 10 1809/1803 兼容：WGC 从 1803 起可用；光标采集等 2004+ API 需运行期判断。
- 不引入 Win7/8 兼容代码，避免拖累 1.x；Win7/8 由 2.0 原生实现。
- 文档补充 OCR 原生 / 模型引擎、模型解压位置、录屏音频与分辨率/帧率说明。

## 7. 测试矩阵

### 7.1 OCR

- 引擎：原生 / 模型；原生语言包缺失。
- 语言：中文、英文、中英混排。
- 内容：文档、代码、UI、聊天记录、深色背景、小字。
- 缩放：100% / 150% / 200% DPI。
- 入口：截图、贴图。
- 指标：准确率、耗时、内存、行顺序；模型首次解压与断网可用。

### 7.2 录屏

- 分辨率：720p / 1080p / 1440p / 4K。
- 帧率：30 / 60。
- 范围：区域 / 窗口；单屏 / 多屏。
- 音频：系统声、麦克风、两者混音；设备切换/拔出。
- 控制：倒计时、暂停/恢复、异常停止、磁盘不足、窗口关闭。
- 时长：短录制、10 分钟、30 分钟。
- 指标：CPU、GPU、内存、丢帧、文件大小、音画同步。

### 7.3 回归

- 现有自动化测试全部通过（当前 66 项）。
- 新增 OCR 双引擎真实识别、结果窗口、设置页、录制参数校验、音频混音/时间戳等单元测试。
- Windows 10 1903/21H2/22H2、150% DPI、双屏环境至少各一轮冒烟。

## 8. 风险与取舍

- **4K60 / 4K<500MB**：WPF 覆盖层和现有录制管线很难同时保证；1.x 以 4K30 稳定为主，4K60 与严格内存目标在 2.0 原生实现。
- **窗口录制**：WGC 窗口捕获在 Win10+ 可行，但窗口缩放、遮挡、关闭和系统边框需要专门处理。
- **音频编码**：Media Foundation 的 AAC/设备兼容性需要实测；不引入 FFmpeg，编码器不可用时需明确回退或提示。
- **OCR 准确率**：Windows OCR 对中文小字/混排有限；PP-OCRv6 tiny 对混排更稳但速度稍慢，两者都不能保证所有样本。模型会增加约 18 MB 运行时与模型体积。
- **WPF 内存**：1.x 无法达到空闲 <100MB；不要用软件渲染或强制 GC 牺牲体验。
- **老 Win10**：1809/1803 的 WGC/光标/API 差异需要运行期判断，不为了兼容牺牲 Win10 主流版本体验。

## 9. 2.0 方向（不在 1.x 实现）

- Windows 原生重构，覆盖 Win7/8/10/11，优先 Qt 5.15/C++ 或 Win32 + C++ 核心；macOS 后续使用 Swift/AppKit。
- 空闲内存目标 40–80MB，4K 录制 <500MB；原生选区覆盖层、GPU 零拷贝、无 WPF 渲染表面。
- Win7/8 分层：区域录制 30fps + 音频；窗口/60fps 仅 Win10+；OCR 在 Win7/8 使用 Tesseract，接受低于 Windows OCR 的准确率。
- 1.x 阶段只做接口/模型隔离，不提前进行原生重写。

## 10. 下一步

1. M1 OCR 已完成并通过手动验收后再发布 v1.4.0；发布前不移动已有 v1.3.1 标签和资源。
2. 进入 M2 录屏视频：分辨率/帧率/画质设置、窗口录制、倒计时、暂停/恢复与 HUD。
3. 完成 M3 音频：WASAPI 系统声与麦克风、AAC、混音与设备处理、音画同步。
4. M4 根据实测决定 1.x 的 4K/内存边界，并把数据带入 2.0 规划。
